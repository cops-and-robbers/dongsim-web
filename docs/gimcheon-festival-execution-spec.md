# 김천 김밥축제 부스 - 실행 스펙 (내부용)

기획안([gimcheon-gimbap-festival-booth-plan.md](gimcheon-gimbap-festival-booth-plan.md))을 실제로 만들기 위한 코드 수정과 디자인 산출물 목록입니다.
심사 제출용이 아니라 팀 작업용입니다. 공수 표기: 소/중/대.

원칙: **로직은 그대로 두고 에셋과 카피만 갈아끼우는 것부터** 합니다. 신규 개발은 최소로 둡니다.

---

## 1. 기존 코드 수정

### A. 웹 미니게임 김밥 리스킨 - `components/booth` (공수: 소)

현재 "치즈 도둑 검거 작전"(9구멍 두더지잡기: 도둑 탭·경찰 피하기)을 김밥 테마로 바꿉니다. **게임 로직(스폰 스케줄, 콤보, 점수, 리더보드)은 건드리지 않습니다.** 에셋 경로와 문구만 교체합니다.

| 파일 | 현재 | 변경 |
| --- | --- | --- |
| `booth/types.ts` | `ROBBER_SRC = /characters/robber.svg` (잡을 대상) | 뚱보 도둥이 아이콘 경로로 교체 |
| `booth/types.ts` | `CIVILIAN_SRC = /characters/police.svg` (감점 대상) | 냥파 아이콘 경로로 교체(치면 감점 = 아군 오인) |
| `booth/types.ts` | `CHEESE_BACK_SRC`, `CHEESE_TOP_SRC` (치즈판 2레이어) | 김밥 도마 보드 2레이어 PNG로 교체. `HOLE_POS`(구멍 9개 %좌표)는 새 보드에 맞춰 값만 조정 |
| `booth/ThiefHuntGame.tsx` | 감점 시 pop 텍스트 `"경찰!"` | 테마 문구로(예: 냥파를 잘못 친 상황 문구) |
| `booth/IntroScreen.tsx` | 제목 "치즈 도둑 검거 작전!", 설명, Legend 라벨(득점/감점) | 김밥 스토리 카피로 교체 |
| `booth/ResultScreen.tsx` | 결과 문구 | 김밥 테마 결과 문구 |
| `booth/Shell.tsx` | 배경 톤 | 축제/김밥 톤(선택) |

주의: 상수 이름(`ROBBER_SRC` 등)은 그대로 두고 경로만 바꿔도 됩니다. 이름까지 바꾸면 참조부(3-4곳) 동시 수정이 필요하니, 시간 없으면 경로만 교체합니다.

### B. 포토부스 축제 프레임 추가 - `components/photobooth/frames.ts` (공수: 소)

4컷 세로 프레임 구조입니다. 새 PNG 한 장 그려서 배열에 항목만 추가하면 됩니다.

```ts
// FRAMES 배열에 추가
{
  id: "gimbap",
  label: "김밥축제",
  src: "/photobooth/frame-gimbap.png",
  swatch: "#2f7d32",
  width: 1364,
  height: 4096,
  slots: SLOTS, // 기존 4슬롯 좌표 그대로 (각 1200x830)
}
```

- 슬롯 좌표는 고정입니다(창 4개 x=82, w=1200, h=830, y간격 895). 새 프레임도 이 창을 비워둔 채 디자인합니다.
- 원하면 `DEFAULT_FRAME`을 축제 프레임으로 바꿔 기본 노출합니다.

### C. 축제 허브 페이지 신규 - `app/festival/page.tsx` (공수: 중)

QR을 찍으면 도착하는 무설치 진입 관문입니다. 라우팅만 모아둡니다.

- 버튼: 앱 설치(스토어 링크), 라운드 참여(초대코드/딥링크), 웹 미니게임(`/booth`), 포토부스 안내, 김천/축제 안내
- 신규 컴포넌트 최소화. 기존 `booth`, `photobooth`로 이동만 시킵니다.

### D. 실시간 현황판 신규 - `app/festival/board/page.tsx` (공수: 중)

부스 대형 화면에 띄우는 집객용 보드입니다. 최대한 재사용합니다.

| 재사용 | 위치 |
| --- | --- |
| 미니게임 순위 | `app/api/booth/scores` |
| 게임 구역/분포 지도 | `components/admin/maps.tsx` (`GameAreaMap`, `GameDistributionMap`) |

- v1: 오늘 참여 수, 미니게임 순위 Top N, 게임 구역 지도.
- 확장(실시간 이동 점): 앱/백엔드의 실시간 위치 피드가 있어야 함 → 2차 과제로 분리.

### E. 앱 GPS 축제 모드 - `cops-and-robbers-FE` + 백엔드 (공수: 대)

여기가 유일하게 무거운 부분이라 **별도 티켓**으로 관리합니다.

- **QR 즉시 참여**: QR → 초대코드 자동 입력 → 다음 라운드 냥파 합류. 딥링크 또는 초대코드 프리필.
- **밥풀 자국**: 도둑 위치 공개마다 지도에 밥풀 마커를 남기고 오래되면 흐려짐(최근 K개 유지). 위치 공개 주기 20-40초 프리셋.
- **이벤트 게임 프리셋**: 라운드 5-8분, 경찰 대기 30-60초, 좁은 폴리곤 구역. 축제장 경계 좌표는 현장 확정 후 입력.

## 2. 디자인 산출물

먼저 그려야 할 것부터 위에 뒀습니다. 공통으로 쓰이는 캐릭터가 최우선입니다.

| 산출물 | 규격/형식 | 쓰이는 곳 |
| --- | --- | --- |
| 뚱보 도둥이 캐릭터 | SVG + PNG(투명), 정면/달리는 포즈 | 미니게임, 포토, 배너, 현황판 공통 |
| 밥풀 마커 | SVG, 작은 밥풀 1알(핫/콜드 2톤) | 앱 밥풀 자국, 현황판 |
| 냥파 캐릭터 | SVG + PNG(투명) | 미니게임 감점 대상, 포토, 배너 |
| 미니게임 보드 | PNG 2장(뒤 구멍/앞 도마), 9구멍 배치, 구멍 %좌표 명시 | `components/booth` |
| 포토 프레임(축제) | PNG 1364x4096, 투명 창 4개(각 1200x830, 좌표 고정), 밥풀/도둥이/냥파 스티커 + "김천김밥축제" 로고 | 포토부스 |
| 부스 배너 | 대형 출력물, 스토리 1컷 + 참여 QR | 부스 정면 |
| QR 스탠드 | A4 거치형, 참여/설치/권한 안내 3스텝 | 진입 동선 |
| 현황판 화면 | 16:9 대형 화면 레이아웃(참여 수/순위/지도) | 부스 스크린 |
| 축제 허브 페이지 | 모바일 세로, 버튼 4-5개 + 김밥 스토리 헤더 | `app/festival` |
| 도둥이 분장 시안 | 배 부픈 패딩 의상 + 소품 참고 이미지 | 스태프 |
| 냥파 소품 | 모자/뱃지 시안 | 방문객 |

디자인 톤: 앱 브랜드색(경찰=파랑, 도둑=초록)을 유지하되, 김밥/축제 느낌(김·밥·단무지 색)을 액센트로. 캐릭터는 기존 냥파/도둥이 톤과 이어지게 합니다.

## 3. 작업 순서 제안

1. 캐릭터(뚱보 도둥이, 밥풀, 냥파) 확정 - 나머지 산출물이 여기서 파생됨
2. 미니게임 리스킨(A) + 포토 프레임(B) - 공수 소, 바로 눈에 보이는 결과
3. 축제 허브(C) + 현황판 v1(D)
4. 앱 축제 모드(E) - 별도 티켓, 백엔드 협의 후 병행
5. 물리 산출물(배너, QR 스탠드, 분장) 발주

**현장 확정 대기**: 축제장 지도(구역 좌표), 부스 위치/전력/와이파이, 라운드 시간표, 상품.
