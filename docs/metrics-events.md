# 일정, 운영진, 행사 성적표 (#165)

지표에 팀 테스트와 행사가 섞이면 숫자가 왜 튀었는지 가리기 어려워요. 그래서 기록 셋을 겹쳐 읽어요.

| 기록 | 답하는 질문 | 어디에 |
|---|---|---|
| 일정 | 그날 무슨 일이 있었나 | `metrics_events`. 성격(행사, 홍보, 출시, 테스트, 기타)으로 나누고, 행사는 시간과 장소까지 |
| 사람 | 누가 했나 | 운영진은 백엔드 `ADMIN` 권한 계정과 `metrics_staff_accounts`에 넣은 계정 |
| 게임 | 어떤 판이었나 | 참가자로 자동 분류: 운영진끼리, 섞임, 사용자만, 명단 없음(2026-08-17 전) |

각 기록이 맡는 일은 하나씩이에요.

- **테스트를 지표에서 빼는 건 사람 기록이 해요.** 일정에 "테스트"를 적어도 그날 숫자를 빼지 않아요. 날짜로 빼면 같은 날의 실제 게임까지 버려요. 10/2는 실제 게임 3판에 운영진 테스트 4판이 섞였고, 10/1~10/3은 잠금 화면 기능을 낸 직후라 실제 사용자가 몰렸어요(10/3 화성 31명 한 판 등).
- **행사를 알아보는 건 일정이 해요.** 행사 판은 운영진이 방장으로 섞여 있어서 사람 기록만으로는 행사인지 몰라요. 일정의 시간과 장소에 맞는 판을 행사 게임으로 봐요.
- 일정에 기간을 쌓지 않아요. 하루 단위로 무슨 일이 있었는지만 적어요.

## 운영진

- `ADMIN` 권한 계정은 자동으로 운영진이에요. 지표가 백엔드 계정 목록을 읽을 때 바로 알아요.
- 권한 없는 팀원 계정과 테스트 계정은 어드민 유저 상세의 "운영진 계정" 스위치로 켜요(`metrics_staff_accounts`).
- 지인이나 QA에 초대한 사람은 켜지 않아요. 실제로 앱을 깔고 해 본 사용자예요.
- 2026-10-11에 지난 게임 455개에서 운영진하고만 했거나 혼자 시험한 계정을 찾아 팀이 확인했어요. 131(팀원), 208, 68, 17(테스트 계정)을 넣었어요. 운영진과 자주 같이 했지만 팀원의 친구인 계정과 3차 QA 참가자는 사용자로 뒀어요.

## 지표에서 세는 법

| 지표 | 규칙 |
|---|---|
| 판 수 | 운영진끼리만 한 판은 빼요. 섞인 판(행사 부스처럼 운영진이 방장)은 세요 |
| 참가 인원 | 시작 명단(중간에 나간 사람 포함)에서 운영진을 뺀 수. 명단이 없는 판만 끝까지 남은 경찰, 도둑 수 |
| 가입, 첫 게임을 한 새 가입자 | 운영진 계정은 빼요 |
| 2026-08-17 전 판 | 누가 했는지 기록이 없어 그대로 세요. 세종대 근처 판을 운영진으로 짐작해 빼지 않아요. 반경을 어떻게 잡느냐에 따라 4월만 47판에서 114판까지 달라져서 믿을 수 없어요 |

참가 인원을 명단으로 바꾼 이유: 판 요약의 경찰, 도둑 수는 끝까지 남은 사람만 세서, 9/19 서대페 판 하나가 명단 24명인데 6명으로 잡혔어요.

화면과 챗봇이 같은 함수(`lib/metrics/gameServer.ts`)로 세요. 예전에는 챗봇만 관리자 판을 빼서 둘의 숫자가 달랐어요. 화면의 "진행된 게임" 칸에 뺀 운영진 판 수를 같이 적어요.

## 일정 성격

| 성격 | 넣는 법 | 지표에서 하는 일 |
|---|---|---|
| 행사 | 달력에서 직접. 시간과 장소(지도에서 복사한 좌표, 반경 300m, 500m, 1km) | 행사 성적표. "평소"를 셀 때 이날은 빼요 |
| 홍보 | 달력에서 직접 | 차트에 표시 |
| 출시 | 수집기가 자동(`appstore/releases.ts`, `play/releases.ts`) | 차트에 회색으로 표시 |
| 테스트 | 달력에서 직접. QA, 팀 시험 | 차트에 표시만. 숫자는 운영진 계정으로 이미 걸러져요 |
| 기타 | 달력에서 직접 | 차트에 표시 |

색은 행사, 홍보, 테스트만 주고(`--ev-event`, `--ev-promo`, `--ev-test`), 출시는 회색, 기타는 글자색이에요. dataviz 검사기로 색약, 밝기, 대비를 라이트와 다크 모두 확인했어요. 색만으로 가르지 않게 범례와 툴팁, 목록에 성격 이름을 같이 적어요.

0007 마이그레이션이 지금 있는 일정을 이름으로 옮겨요(`출시$` 출시, QA/테스트/시험 테스트, 부스/축제/vs 행사, 홍보/포스터/광고 홍보). 마이그레이션 전에는 화면이 같은 규칙으로 짐작해 보여 줘요(`events.ts guessCategory`).

## 행사 게임 찾기

같은 날, 행사 시작 30분 전부터 끝날 때까지 시작했고, 게임 구역 가운데가 행사 장소 반경 안인 판이에요(`events.ts isEventGame`).

- 부스를 열기 전에 방을 만들어 두는 일이 많아 30분 앞을 봐요
- 장소를 모르면 시간만, 시간을 모르면 장소만 봐요. 둘 다 모르면 찾지 않아요. 그날 모든 판이 행사 판이 되어 버려요
- 같은 날 두 행사(9/19 서대페 반포, 청춘대로 어린이대공원)도 장소로 갈라져요
- 지난 행사 장소는 그날 게임 구역의 가운데로 넣었어요. 노원 축제(10/24)는 좌표를 확인하지 못해 시간만 넣었어요. 달력에서 그날을 누르고 고치기로 넣어요
- 백엔드에 이벤트 게임 표시와 방장 기록이 생기면(BE #213) 그것도 같이 써요

## 행사 성적표

요약 탭 일정 달력 위에 있어요(`EventReport`, `/api/admin/metrics/event-report`, 계산은 `lib/metrics/eventReport.ts`).

- **행사 게임:** 판 수(운영진끼리 시연한 판 포함), 방문객과 운영진 참가 수(판마다 더한 수), 판마다 시작 시각과 진행 시간
- **그날 숫자와 평소:** 스토어 최초 설치, 앱 첫 실행, QR과 다운로드 링크로 스토어 이동, 가입, 첫 게임을 한 새 가입자, 그날 진행된 게임
- **평소:** 앞선 같은 요일 네 번의 평균. 다른 행사 날은 건너뛰고 8주 앞까지 채워요. 행사가 주말에 몰려 요일을 맞춰요
- 운영진을 빼지 않고 나눠 보여 줘요. 지표 화면은 "사용자가 늘고 있나", 성적표는 "행사에서 무엇을 했나"를 묻는 화면이라서예요
- 차이는 "같은 날 함께 나타난 숫자"라고 적어요. 행사만의 효과라고 단정하지 않아요
- 아직 열리지 않은 행사는 준비 상태(시간, 장소)를 보여 줘요
- 2026-08-17 전 행사(7/4 서울게임타운)는 명단이 없어 방문객이 끝까지 남은 인원만 잡혀요. 화면에 그렇게 적어요
