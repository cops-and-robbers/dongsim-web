# 어드민 UI 설계 노트

관리자 화면을 만들면서 UI/UX로 고민하고 정한 것들을 남겨요. "왜 이렇게 했나"가 중심이에요.

## 무드

"테두리로 칸칸 나눈 전형적인 엔터프라이즈 어드민"은 피하고, 토스처럼 담백하고 정보가 또렷한 무드로 잡았어요. 여백과 색으로 정보를 나누고, 불필요한 선·박스는 줄였어요.

## 디자인 토큰 (라이트·다크 자동 대응)

색을 하드코딩하지 않고 시맨틱 토큰(`sd-*`)으로 썼어요. 라이트/다크에서 값이 자동으로 뒤집혀요.

- 액센트는 라이트=경찰=파랑, 다크=도둑=초록이에요. (두 진영이 대등한 우리 원칙 그대로요.)
- 상태색은 info(파랑)·positive(초록)·warning(앰버)·critical(빨강)으로 통일했어요.
- 표면·경계·글자는 surface / line / fg 계열로 묶었어요.

## 대시보드(개요) - "숫자 나열" 탈출

그냥 숫자만 늘어놓지 않으려고 했어요.

- 지금 챙길 것(진행중 게임·미처리 신고·미처리 버그)을 상단 카드로 뽑았어요.
- 오늘의 지표는 한 줄 스트립으로 묶었어요.
- 게임 종료 사유는 도넛, 팀별 승률은 막대로 시각화했어요.
- 게임이 없거나 유저가 없어도 빈 상태·스켈레톤이 항상 자리를 지켜요. (데이터가 없다고 레이아웃이 무너지지 않게요.)

## 색으로 상태를 말하기

카드 배경을 덕지덕지 칠하는 대신, 숫자·아이콘·문구의 색으로 상태를 전해요.

- **처리 대기(신고·버그)** = 빨강(critical). "확인이 필요해요"
- **0건(모두 처리)** = 파랑(info). "모두 처리됐어요" (대기=빨강 / 완료=파랑 대칭이에요.)
- **진행중 게임** = 액센트 카드
- 하늘색은 액센트(파랑)와 겹쳐서 안 썼어요. 파랑은 "주의"가 아니라 "정보"로 읽혀서요.
- 아이콘을 색 네모 박스에 가두지 않고 상태색만 입혔어요. 카드 색과 이중으로 튀지 않게요.

## 아이콘 - 손으로 그리지 않기

아이콘은 직접 그려서 어설프게 만들지 않고, 검증된 아이콘셋(Lucide) 원본 path를 그대로 가져와 stroke만 우리 셋에 맞췄어요.

- 개요 = `activity` (실시간 맥박 느낌)
- 게임 = `gamepad-2`
- 신고 = `siren` (경찰과 도둑 테마에 맞게요.)
- 버그 = `bug`

안드로이드·소셜 같은 브랜드 마크는 색 자체가 의미라 별도 파일로 관리해요.

## 내비게이션 - 역할별 그룹

메뉴 6개를 평평하게 두지 않고 역할로 묶고, 그룹 사이에 얇은 구분선을 뒀어요.

- 개요
- (데이터) 유저 · 게임 - 주로 조회·드릴다운 대상이에요.
- (처리) 신고 · 버그 - 직접 손대야 하는 미처리 큐예요.
- (콘텐츠) 공지 - 유일한 발행이에요.

## 게임 종료 사유 라벨

"몰수"는 무슨 상황인지 안 읽혀서, 백엔드 로직을 보고 "기권"으로 바꿨어요.

- 경찰 기권 = 인게임 중 마지막 경찰이 나가서 도둑 승 (이벤트 게임은 제외)
- 도둑 기권 = 마지막 생존 도둑이 나가서 경찰 승

## 모바일

데스크톱은 사이드바, 모바일은 하단 탭 + 상단 헤더예요. 상세는 모바일에서 풀스크린 모달로 떠요.

## 스케일 주의 (백엔드 값 그대로 읽기)

- 팀 승률은 백엔드가 이미 0~100 퍼센트로 줘요. 프론트에서 또 ×100 하지 않아요.
- 평균 게임 시간은 백엔드 AVG라 소수가 와요. 표시 전에 정수 초로 반올림해요.
