# 검색 색인 현황 (#309)

새 페이지가 생기면 검색엔진에 알리고, 구글에 올라갈 때까지 어드민이 따라간다. 사람은 손댈 일이 있을 때만 본다.

#299 때 색인 요청을 37번 눌러도 75개 중 7개였다. 그것도 서치 콘솔을 하나씩 열어 보고서야 알았다. 숫자를 옮겨 오는 보고 화면보다, 언제 왜 이걸 보러 오는지에 맞춰 짰다.

## 보러 오는 순간

| 순간 | 들어오는 길 | 보여 줄 것 |
| --- | --- | --- |
| 새 글을 올린 날 | 블로그 화면 동기화 | 동기화 결과 아래 "글 N개를 구글과 빙·네이버에 알렸어요" 한 줄 |
| 며칠 뒤 안 올라왔을 때 | 지표 검색 탭 블로그 글 표 | 상태 옆 "N일째", 누르면 판정과 뜻, 서치 콘솔로 가는 버튼, "요청했다고 남기기" |
| 한 주 돌아볼 때 | 지표 검색 탭 | 클릭수, 노출수, 검색어, 새로 색인된 글 |
| 뭔가 깨졌을 때 | 지표 검색 탭 사이트 페이지 표 맨 위 | 빨간 "오류" 칸, 누르면 언제부터 무슨 오류인지 |
| 다음 글을 고를 때 | 지표 검색 탭 검색 실적 | 평균 게재순위 8~20위 검색어, 앱 이름이 아닌 검색 |

블로그 화면 칩, 개요 "지금 할 일", 디스코드 알림, 일정 자동 추가, 추세 차트는 다음 단계다.

## 흐름

```
새 주소 ─▶ 검색엔진에 알림 ─▶ 매일 구글 판정 ─▶ 7일 지나도 안 되면 사람이 서치 콘솔에서 요청 ─▶ 색인되거나 30일
```

- **새 주소를 찾는 곳은 둘이다.** 블로그 동기화(`/api/blog/sync`, 버튼과 6시간 크론이 모두 여기로 온다)에서 이번에 처음 공개된 글과 공개된 채로 고친 글. 매일 수집에서 사이트맵을 어제까지 본 주소와 비교해 모집글, 고정 페이지
- **알림**: 구글은 서치 콘솔 API 로 사이트맵을 다시 제출한다(구글은 2023년에 사이트맵 핑 주소를 없앴다). 빙, 네이버 등은 IndexNow 로 주소를 보낸다. 한 곳에 보내면 참여한 검색엔진끼리 나눠 갖는다(Bing, Yandex, Seznam, Naver, Yep, Internet Archive, Amazonbot, 2026-11-11 `indexnow.org/searchengines.json`). 구글은 IndexNow 에 참여하지 않는다
- **추적**: 새 주소는 30일 동안 매일 URL 검사로 판정을 받는다. 처음 읽힌 날, 색인된 날을 `search_tracking` 에 남긴다. 모집글은 며칠 뒤 마감되는 짧은 페이지라 알리기만 하고 따라가지 않는다
- **사람 한 번**: 구글 색인 요청은 API 가 없다(Indexing API 는 채용 공고와 라이브 방송 페이지 전용). 7일이 지나도 안 되면 표에 "N일째"로 드러나고, 사람이 서치 콘솔에서 누른 뒤 "요청했다고 남기기"를 누른다. 남긴 주소는 다시 표시하지 않는다

처음 수집이 돌 때 사이트맵에 있던 주소는 `origin = baseline` 으로만 남기고 따라가지 않는다. 모두 새 주소로 보면 알림이 쏟아진다.

## 쓰기 동작의 규칙

- 사이트맵 제출과 IndexNow 는 **운영 배포에서만** 보낸다(`VERCEL_ENV === "production"`). 미리보기와 로컬은 운영과 같은 DB 를 쓰고, 아직 없는 주소를 알릴 수 있다
- 보낸 것은 모두 `search_actions` 에 남긴다(무엇을, 어떤 주소를, 누가. 자동이면 "자동", 동기화면 "블로그 동기화")
- 같은 사이트맵 제출은 3분 안에 다시 하지 않는다(출시 조작과 같은 시간)
- 몇 번 보내도 결과가 같고 사용자에게 닿지 않는 동작이라 확인창을 두지 않는다
- 알림이 실패해도 블로그 동기화는 실패시키지 않는다. 발행은 이미 끝났다. 응답의 `search` 에 담는다

## 화면 (지표 > 검색)

숫자 칸, 카드, 진행 막대, 색 배지를 늘어놓지 않고 표 두 개와 문장 한 줄로 읽히게 했다. 첫 판(카드와 막대, 31줄 표)을 Codex 와 제미나이에 보여 주고 "AI 가 만든 화면처럼 보이는 곳"을 따로 판정받아 고쳤다.

- **맨 위는 답 한 문장**: "31개 중 10개가 구글에 올라가 있어요". 그 아래 한 줄이 상태별 개수를 색 글자로 보여 주고(올라감, 보류, 안 읽음, 제외, 오류), 7일 전과의 차이와 확인한 날을 붙인다. 이 줄이 표의 범례를 겸한다
- **"페이지 | 검색 실적"을 나눠 본다.** 판정은 오늘 아침 것이고 실적은 위의 기간을 따라서, 기준이 다른 숫자를 한 화면에 섞지 않는다
- **사이트 페이지 표**: 같은 페이지가 세 언어로 있어서 한 줄에 한국어, 영어, 일본어 칸을 둔다(번역 상태 표처럼). 칸에는 상태와 구글이 읽은 날. 문제가 있는 페이지가 위로 온다
- **블로그 글과 모집글 표**: 글마다 언어가 하나라 제목, 상태, 구글이 읽은 날, 노출을 좁은 열로 붙인다. 손댈 것부터, 새 글 먼저. 7일 넘게 멈춘 새 글은 상태 옆에 "N일째"
- **색은 문제가 있는 글자에만 쓴다.** 오류 빨강, 보류(크롤링됨, 색인 안 됨) 노랑, 올라감 초록, 나머지는 흐린 글자. 같은 "색인 안 됨"이라도 할 일이 달라 말을 나눈다. 오류는 우리가 고칠 일, 보류는 구글의 판단, 안 읽음은 기다릴 일이다. 구글 문서도 뒤의 둘은 대개 문제가 아니라고 적는다
- **목록에 이미 보이는 문제는 위에 따로 띄우지 않는다.** 오류 페이지와 오래 멈춘 새 글은 표 맨 위에 있다. 표에 안 보이는 것(새 숫자를 이틀 넘게 못 받음, 사이트맵 오류)만 맨 위 한 줄로 띄운다
- **상태 말은 짧게, 서치 콘솔 이름은 상세에서**: 표 칸은 좁아 "보류" 같은 짧은 말을 쓰고, 칸을 누르면 오른쪽(폰은 아래) 상세에 서치 콘솔 표기와 뜻, 날짜순 기록(처음 봄, 알림, 요청, 구글이 읽음, 상태 바뀜), 대표 주소, 사이트맵, 가져오기, "서치 콘솔에서 열기"가 있다
- **실적 보기**: 노출, 클릭, 클릭률, 평균 순위를 숫자 한 줄로(문장 속에 묻지 않는다), 날마다 차트(이전 기간 비교선, 일정 마름모), 검색어 표(전체, 앱 이름, 그 밖의 검색, 8-20위)
- **실적은 구글이 채운 날까지만 비교한다.** 구글은 2~3일 늦게 확정한다. 이번 기간이 덜 찬 만큼 이전 기간도 잘라야 늘 줄어든 것처럼 보이지 않는다(Google Play 와 같은 처리)
- **평균 게재순위는 노출수로 가중해** 다시 계산한다. 날짜나 검색어의 평균을 다시 평균 내면 틀린다
- **앱 이름 검색**: "경찰과 도둑", "경도"는 놀이 이름이기도 해서 그것만으로는 우리를 알고 찾았는지 모른다. 앱, 어플, 다운 같은 말이 같이 있거나 팀 이름, 영문 이름일 때만 센다(`isBrandQuery`)
- **8-20위**: 평균 게재순위 8~20위. 제목과 내용이 검색어에 맞는지 살펴볼 검색어. 평균 순위로 "1쪽 바로 아래"라고 위치를 단정하지 않는다(Codex 검토)
- 검색 탭은 다른 지표를 기다리지 않고 먼저 연다. 지표가 오면 비교 기간과 일정 표시를 더한다
- 이름은 주소 대신 사람이 부르는 이름을 쓴다(`lib/search/names.ts`: 블로그는 글 제목, 고정 페이지는 메뉴 이름)

### 근거

- 요약 먼저, 거르기, 누르면 상세(Shneiderman 의 정보 탐색 원칙, 1996)
- 평소엔 조용히, 예외만 부르기. 대부분의 새 글은 알아서 올라가니 사람에게는 7일이 지나도 안 될 때와 오류만 보인다
- 자동과 사람의 경계는 API 가 정한다. 사이트맵 제출과 IndexNow 는 API 가 있어 자동, 색인 요청은 없어서 사람
- 다국어 사이트는 "페이지 × 언어" 표가 상태를 가장 빨리 읽게 한다. 같은 페이지의 세 언어가 흩어져 있으면 한 언어만 깨진 것을 놓친다

## 데이터

`supabase/migrations/0027_search_console.sql`

| 표 | 한 줄 | 채우는 곳 |
| --- | --- | --- |
| `gsc_inspection_daily` | 날짜, 주소 하나의 구글 판정 | 매일 수집. 사이트맵 주소 + 따라가는 주소 + 최근 28일 검색에 나온 우리 주소(상한 300) |
| `gsc_search_daily` | 날짜, 나눔(total, page, query, country, device), 키의 클릭수, 노출수, 게재순위 | 매일 수집. 최근 10일 다시 받음. 날짜는 구글이 주는 미국 서부 날짜 |
| `gsc_sitemap_daily` | 날짜별 사이트맵 제출일, 구글이 읽은 날, 오류·경고, 주소 수 | 매일 수집 |
| `search_tracking` | 주소 하나의 흐름 | 동기화, 매일 수집, "요청했다고 남기기" |
| `search_actions` | 밖에 보낸 것과 요청 기록 | 쓰기 동작마다 |
| `blog_sync_runs` | 동기화 한 번의 결과(새로 공개, 고침, 내림, 실패 수) | `/api/blog/sync`. 크론 결과가 다른 곳에 남지 않아서 |

코드: `lib/search/`(API 클라이언트, 판정 읽기, 화면 데이터 계산, 수집), `app/api/metrics/gsc`(수집), `app/api/admin/search`(화면 데이터, 요청 기록), `app/indexnow-key.txt`(IndexNow 키 파일), `components/admin/metrics/SearchTab.tsx`(화면). 로컬은 MSW 가짜 응답(`lib/admin-mock/search.ts`)이 실제 계산을 거쳐 답한다.

## 처음 켜기

1. Supabase SQL Editor 에서 `0027_search_console.sql` 실행
2. 구글 클라우드(지표 수집 서비스 계정이 있는 프로젝트)에서 **Google Search Console API** 사용 설정
3. 서치 콘솔 > 설정 > 사용자 및 권한 > 사용자 추가: 서비스 계정 `metrics-collector` 이메일. 사이트맵 제출까지 하려면 **전체** 권한(제한된 권한은 읽기만 된다)
4. Vercel 환경변수 `INDEXNOW_KEY`: 영문, 숫자, 대시 8~128자. 아무 값이나 만들면 된다. 배포 뒤 `https://copsandrobbers.app/indexnow-key.txt` 가 그 값을 내주는지 본다
5. 손으로 한 번: `node --env-file=.env.local scripts/metrics-collect.mjs gsc --dry` 로 권한을 확인하고, `--from all` 로 검색 실적을 4월부터 채운다. 첫 실행이 사이트맵 주소를 baseline 으로 남긴다

## 하지 않는 것

- 구글 색인 요청 자동화(API 없음), Indexing API(대상 페이지가 아님)
- 모집글 구글 추적(짧은 페이지)
- 고친 글을 새 글처럼 30일 다시 따라가기: 알리기만 하고, 추적은 처음 공개될 때만 한다
- 지표 챗봇의 검색 지표: 검색 탭에서 물으면 지금은 유입 경로 탭을 보며 묻는다
